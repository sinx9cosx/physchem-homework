## 一、整体架构建议：增加“过程类型”顶层切换

在标题附近增加一个 **过程类型切换器**，作为最高层状态：

```html

  <strong>过程类型：</strong>
  <button id="modeIsobaric" class="mode-btn active">恒外压（体积功）</button>
  <button id="modeIsochoric" class="mode-btn">恒容（变温）</button>
```

**核心逻辑：**
- `processMode = 'isobaric'`（默认）：显示现有全部控件，上下两块分别演示恒外压不可逆/可逆。
- `processMode = 'isochoric'`：**固定活塞位置**，上下两块切换为恒容模式。
  - 上块：**不可逆恒容**（如定容下系统与高温/低温热库突然接触）。
  - 下块：**可逆恒容**（准静态地逐步改变系统温度）。

## 三、物理模型与算法设计

### 1. 不可逆恒容（上块画布）

**物理图像：** 活塞被插销固定，体积恒定。将气体突然与温度为 $T_{\text{target}}$ 的热库接触，观察其趋向平衡。

**MD 算法修改：**
- `xP` 固定为初始值，`vP = 0`。
- 取消外压 `Pext` 和阻尼对活塞的影响。
- **热浴驱动：** 若选择“等温热浴（简化重标定）”，则将重标定的目标温度从 `initialTemp0` 改为 `T_target`。
  - 使用有限速率的恒温器
  
  ```Javascript
  // 温和重标定，而非一步到位
  const rate = 0.3; // 可调参数
  const lambda = 1 + rate * (Math.sqrt(T_target / T_current) - 1);
  for (const p of particles) {
  p.vx *= lambda;
  p.vy *= lambda;
  }
  ```
  - 累计热量 `q += ΔK_bath`。
  - 由于 $w=0$，应有 $\Delta U \approx q$（二维单原子气体 $U=K$）。
- **可视化：** 压力 $P = NkT/V$ 会随温度变化而线性变化；体积为平线。

### 2. 可逆恒容（下块画布）

**物理图像：** 活塞被锁定，但热浴温度被程序控制，从 $T_0$ 开始，每步只增加微量 $dT$，中间充分弛豫，使系统始终近似平衡。

**MD 算法修改：**
- 类似可逆模块，但把 **“活塞微移 dx”** 替换为 **“目标温度微增 dT”**。
- 每步：
  1. 更新当前步目标温度 `T_step = T0 + (T_target - T0) * (currentStep / totalSteps)`
  2. 运行若干弛豫步（粒子运动 + 碰撞，固定活塞）
  3. 使用温和恒温器（`gentleThermostat`）向 `T_step` 弛豫
  4. 记录 $P = NkT/V$（应接近平衡值）
- **功的计算：** $w_{\text{rev}} = 0$（活塞不动，无边界位移功）。
- **热量计算：** $q_{\text{rev}} = \Delta U = N C_V \Delta T$。二维单原子理想气体 $C_V = Nk$（每粒子 $k$），所以 $\Delta U = N(T_f - T_i)$（因 $k=1$）。

## 四、过程图与能量图的适配

### 跟踪图（Trace Canvas）
恒容模式下，建议纵轴替换为 **温度 T**（或保持 P，因为 P∝T）：

- **蓝色曲线：** $P_{\text{gas}}$（或 $T_{\text{kin}}$）—— 随时间上升/下降
- **红色实线：** $V$ —— **严格的水平直线**（这是恒容最核心的视觉证据！）
- **橙色虚线：** $V_0$ 参考线（与红线重合，可标注“恒容”）

### 能量图（Energy Canvas）

- **黑色 $\Delta U$：** 随温度变化而单调上升/下降
- **蓝色 $w_{\text{ext}}$：** **严格为零的水平线**（或取消不画）
- **青色 $w_{\text{coll}}$：** **严格为零**（活塞不动，无碰撞做功）
- **橙色 $q$：** 与 $\Delta U$ 基本重合，直观展示 **$\Delta U = q_V$**

## 六、代码层面需特别注意的 3 个坑

### 1. 热边界条件（heatMode）在恒容下的建议方案
| 模式 | heatModeSelect 行为 | 语义 |
|------|-------------------|------|
| 恒外压 | 保留原有 | 绝热壁 / 等温热浴 |
| 恒容（不可逆上块） | **隐藏**，改为显示"热库温度跃迁：系统突然接触 $T_\text{target}$ 热库" | 主动控温，不可逆 |
| 恒容（可逆下块） | **隐藏**，改为显示"热库温度线性扫描：从 $T_0$ 到 $T_\text{target}$" | 主动控温，可逆渐变 |

实现上可以把 heatModeSelect 外层包一个 <div id="heatModeWrapper">，恒容模式下 display: none。

### 2. 活塞碰撞功 $w_{\text{coll}}$ 的残留
在恒容模式下，即使活塞位置固定，粒子仍可能与活塞壁碰撞。您的代码中 `revStepMoveAndCollide` 和 `stepOne` 都有活塞碰撞逻辑。恒容模式下必须：
- 将活塞视为 **普通固定硬壁**（与左壁等价），碰撞时速度反向，**不累计** `workMicro`。
- 或更简单：在恒容分支的代码中，直接跳过活塞碰撞做功计算，设 `workMicro = 0`。

### 3. 局部压力估算的失效
您的局部压力估算 `pRightSmooth` 依赖于活塞附近的动量通量。恒容模式下活塞不动，这部分仍然有效（粒子撞固定壁），但左右压力应趋于一致（平衡态）。可以正常显示 $P_{\text{left}}$ 和 $P_{\text{piston}}$，但预期它们会重合得很好。
